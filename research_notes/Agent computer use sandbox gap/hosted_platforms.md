# Hosted / Commercial Sandboxed Computers for AI Agent Computer Use (state as of 27 November 2026)

Research date: 2026-11-27. Vendor pages were fetched on that date unless a different "as of" date is given. Third-party comparison articles used: Simular (vendor pages read 10 Oct 2026), Pinggy and DEV Community (data as of 26 Sep 2026), Fly.io (published 9 Sep 2026). Where third-party and vendor figures conflict, both are recorded.

## Q1. Which hosted platforms provide full GUI desktops for computer-use agents, and what exactly does each provide (tech, boot, snapshots, concurrency, duration, OS, streaming, recording, monitoring, MCP, SDKs, self-host, OSS, pricing, free tier)?

### Takeaway
As of November 2026 the hosted full-desktop field for third-party developers has narrowed to a small set: E2B Desktop (Linux, Firecracker), Daytona Computer Use (Linux and Windows, plus macOS sandboxes), Orgo (Linux, Windows add-on, limited Mac and iPhone), Microsoft Windows 365 for Agents (Windows and Linux Cloud PCs, GA June 2026, but enterprise/Microsoft-ecosystem oriented), Alibaba AgentBay (Windows desktop and Android), plus smaller players (Simular box, InstaVM, Morph Cloud remote-desktop recipe, Runloop Computer add-on beta). Several 2025-2026 desktop providers exited: Scrapybara (shut 15 Oct 2025), Cua Cloud/Fleets (ended 18 Oct 2026), Cloudflare Sandbox desktop (removed), and the Bytebot repo (archived Mar 2026).

### Cited Findings

#### E2B Desktop Sandbox (Linux)
- Desktop image is Ubuntu 22.04 with XFCE and pre-installed apps; live view uses VNC streaming obtained via `sandbox.stream.start()` and `sandbox.stream.getUrl()`; examples use 1024x720 at 96 DPI and a 300 s timeout ([E2B docs, computer use](https://docs.e2b.dev/use-cases/computer-use)).
- Desktop SDK actions: screenshots; mouse click (left/right/middle/double), scroll, move, drag, press/release; keyboard write (adjustable typing speed) and key combos; window listing/titles; launch apps, open files, run bash ([e2b-dev/desktop GitHub](https://github.com/e2b-dev/desktop)).
- Streaming limits: "There can be only one stream at a time"; options `view_only` and `require_auth` (auto-generated key); can stream a full desktop or a single window ([e2b-dev/desktop GitHub](https://github.com/e2b-dev/desktop)). Simular also notes "One stream per desktop at a time" ([Simular comparison, read 10 Oct 2026](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents)).
- SDK languages: Python (`e2b-desktop`) and JavaScript (`@e2b/desktop`); desktop repo is Apache-2.0, ~1.6k stars; SDK sources moved into the E2B monorepo ([e2b-dev/desktop GitHub](https://github.com/e2b-dev/desktop)). Core runtime is open source (Apache-2.0, ~13.4k stars) and self-hostable ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents)).
- Virtualization: Firecracker microVM; ~150 ms start; pause ~4 s per GiB RAM; resume ~1 s; pause keeps memory and disk indefinitely ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents); [Pinggy, data as of 26 Sep 2026](https://pinggy.io/blog/best_cloud_computers_for_ai_agents/)).
- Plan limits (official docs): Hobby $0 with $100 one-time credit, max 8 vCPU / 8 GiB, 10 GiB disk, 1 h max continuous runtime, 10 concurrent sandboxes, creation rate 1/sec; Pro $150/month, 24 h continuous runtime, 100 concurrent sandboxes expandable with add-ons of 500 slots for $500/month up to 1,100, creation 5/sec; Enterprise 1,100+ concurrent, custom. Pausing resets the continuous-runtime window; paused sandboxes have unlimited retention; billing is per second while running and stops when paused/killed/timed out ([E2B billing docs](https://docs.e2b.dev/billing)).
  - Conflict: third parties list Hobby concurrency as 20 ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents); [Fly.io, 9 Sep 2026](https://fly.io/learn/ai-sandbox-pricing/)) versus 10 in the official docs ([E2B billing docs](https://docs.e2b.dev/billing)).
- Rates: $0.0504/vCPU-hr and $0.0162/GiB-hr, about $0.166/hr for 2 vCPU / 4 GiB (derived) ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents); [Fly.io](https://fly.io/learn/ai-sandbox-pricing/)). Multi-day sessions are enterprise-only ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents)).
- E2B Desktop and Daytona were the two launch providers for Mastra's "Sandbox Computer Use" (11 `computer_*` tools), post dated 2 Sep 2026 ([Mastra blog](https://mastra.ai/blog/introducing-sandbox-computer-use)). OpenAI's computer-use guide lists E2B Desktop as a recommended hosted environment ([OpenAI computer use guide](https://developers.openai.com/api/docs/guides/tools-computer-use)).

#### Daytona Computer Use (Linux, Windows; macOS sandboxes)
- Computer Use available for Linux and Windows; starting it launches Xvfb, xfce4, x11vnc and noVNC in the sandbox; VNC for human interaction, Computer Use API for agents; macOS documented as a separate sandbox type ([Daytona Computer Use docs](https://www.daytona.io/docs/en/computer-use/)).
- API surface: mouse (click/move/drag/scroll/hold), keyboard (type, hotkeys, hold/release, f1 to f24), AT-SPI accessibility tree (get/find/focus/invoke/set value), screenshots (full/region/compressed PNG or JPEG), screen recording (start/stop/list/get/delete/download plus a "recording dashboard"), display (resolution, windows), per-process status/restart/logs/errors ([Daytona Computer Use docs](https://www.daytona.io/docs/en/computer-use/)).
- SDKs: Python, TypeScript, Ruby, Go, Java plus REST under `proxy.app.daytona.io/toolbox/{sandboxId}/computeruse/` ([Daytona Computer Use docs](https://www.daytona.io/docs/en/computer-use/)). MCP server available in CLI ([DEV Community comparison, data 26 Sep 2026](https://dev.to/saptadev27/cloud-computers-for-ai-agents-in-2026-a-practical-comparison-5dbd)).
- Isolation: Linux containers by default, VM optional; containers keep filesystem on stop, VMs keep filesystem and memory on pause; 15-minute default auto-stop (can be set to never; background processes do not reset it); default 4 vCPU / 8 GiB per-sandbox cap unless raised ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents)). Daytona's CEO claims a new sandbox can be configured in 60 ms ([tech.eu, 6 Feb 2026](https://tech.eu/2026/02/06/daytona-raises-24m-series-a-to-build-agent-native-compute-infrastructure/)).
- Pricing (official, per-second billing): vCPU $0.0504/h; memory $0.0162/GiB/h; storage $0.000108/GiB/h after first 5 GiB free; Windows OS $0.0858/vCPU/h; macOS $0.0082/core/h; preemptible GPUs from RTX 4090 $0.57/h to B300 $5.17/h; $200 free compute; startups up to $50k credits; Enterprise adds SSO, audit logs, BYOC ([Daytona pricing](https://www.daytona.io/pricing)). (Unclear from the page whether the Windows and macOS rates replace or add to the base vCPU rate.)
- Org-wide resource tiers (not per-sandbox concurrency counts): Tier 1 (email verified) 10 vCPU / 10 or 20 GiB RAM (page is inconsistent) / 30 GiB; Tier 2 ($25 top-up) 100 vCPU / 200 GiB; Tier 3 ($500 top-up) 250 vCPU / 500 GiB; Tier 4 ($2,000 every 30 days) 500 vCPU / 1,000 GiB; sandbox creation 300 to 600 per minute by tier; Enterprise custom ([Daytona limits docs](https://www.daytona.io/docs/en/limits/)).

#### Orgo (Linux; Windows add-on; Mac and iPhone limited)
- Plans: Pay-as-you-go $0 (hourly only); Starter $29/mo (1 always-on Medium); Growth $99/mo (4 Medium); Scale $399/mo (16 Medium, 25 teammates); Enterprise custom (over 999 computers, dedicated hosts, SLA) ([Orgo pricing.md](https://www.orgo.ai/pricing.md)).
- Sizes and hourly rates: Small 0.5 vCPU / 4 GB $0.023/h; Medium 2 vCPU / 8 GB $0.055/h; Large 4 vCPU / 16 GB $0.11/h; XL 6 vCPU / 32 GB $0.202/h; 2XL 8 vCPU / 64 GB $0.368/h; stopped computers bill a small storage rate (e.g. Medium $0.0027/h) ([Orgo pricing.md](https://www.orgo.ai/pricing.md)).
- OS: Linux all plans; Windows $15/mo per computer on Starter/Growth, included on Scale; Mac from $100/mo "when in stock" (M4 VM), M6 VM $120/mo; iPhone 12 $65/mo when in stock ([Orgo pricing.md](https://www.orgo.ai/pricing.md)).
- Concurrency and rate limits: "no limit" on running computers; up to 999 per account; agent runs at once Free 1 / Starter 5 / Growth 20 / Scale 50; new computers per minute 2 / 10 / 30 / 60; control calls per minute per account 300 / 1,500 / 3,000 / 6,000; 600 per computer on every plan ([Orgo pricing.md](https://www.orgo.ai/pricing.md)).
- Features: live desktop, computer-control API, Python SDK, OpenAI-compatible API, 1-click cloning, SSH, real-time collaborative canvas (Growth/Scale) ([Orgo pricing.md](https://www.orgo.ai/pricing.md)); hosted MCP server, share/clone/snapshot running computers ([orgo.ai/pricing](https://orgo.ai/pricing)); MCP server exposing 51 tools ([DEV Community](https://dev.to/saptadev27/cloud-computers-for-ai-agents-in-2026-a-practical-comparison-5dbd)). Homepage title claims "Full cloud computers in under 500ms. Linux and Windows available" ([orgo.ai](https://orgo.ai/?r=phil)).
- Free tier: $3 starting credit (about 54 Medium hours); files kept 7 days after credit runs out ([Orgo pricing.md](https://www.orgo.ai/pricing.md)). Conflict: Simular (10 Oct 2026) says no free tier and lists Starter as 8 GB / 40 GB with $5 AI credit and extra computers $25 each ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents)); an older listing described a "Hacker" plan at $29 with 5 computers ([Orgo search snippet, older](https://orgo.ai/pricing)), so the plan structure changed during 2026.

#### Microsoft Windows 365 for Agents (Windows and Linux Cloud PCs)
- Covered in detail under Q2 (hyperscalers). Key: GA week of 1 June 2026, $0.40/hr US pay-as-you-go rounded up to the hour, pooled check-out/check-in Cloud PCs reset after each session, MCP-based agent channel, Intune-managed ([Microsoft Learn what's new](https://learn.microsoft.com/windows-365/agents/whats-new); [Microsoft Learn pricing](https://learn.microsoft.com/en-us/windows-365/agents/pricing-paygo-always-available)).

#### Alibaba Cloud Wuying AgentBay (Windows desktop, Android, browser, code)
- Four modes: Browser Use, Computer Use (cloud desktops), Code Space (cloud IDE), Mobile Use (cloud phones/tablets) ([Alibaba Cloud blog](https://www.alibabacloud.com/blog/unlock-the-future-of-automation-introducing-alibaba-cloud-agentbay_602649)).

- Streaming uses Wuying's proprietary ASP protocol designed for human/AI handoff ([arXiv AgentBay paper](https://arxiv.org/html/2512.04367v1)).
- Pricing in points: cloud computer and cloud phone ~1.43 points/hour, browser and code space ~0.71 points/hour; one-time 100-point trial coupon ([AgentBay trial page](https://www.alibabacloud.com/help/en/agentbay/product-overview/new-user-trial-instructions)); free Basic plan plus subscription and pay-as-you-go; an "Ultra" plan example uses peak concurrency 300 ([AgentBay billing](https://www.alibabacloud.com/help/en/agentbay/product-overview/agentbay-billing-instructions)). MCP server was in public beta limited to 10 API keys (date unclear, possibly outdated) ([mcpservers.org listing](https://mcpservers.org/ja/servers/Michael98671/agentbay)).

#### Simular "box" (Linux desktop, new entrant)
- Announced 12 Nov 2026, beta: cloud computer with shell, browser and desktop control; works with Claude Code, Codex, Cursor, OpenClaw, Hermes; persistent logins/files ([Simular announcement](https://www.simular.ai/articles/box-by-simular-the-computer-your-agents-needs)).

Note: this comparison is written by the vendor of box.

#### InstaVM (Linux desktop)

#### Runloop (Linux desktop add-on, beta)

- Devbox CPU $0.108 and memory $0.0252 per unit (AWS Marketplace listing; units ambiguous) ([AWS Marketplace Runloop](https://aws.amazon.com/marketplace/pp/prodview-6v2m5a6coprts)); trial devboxes max keep-alive 1 hour ([Runloop trial docs](https://docs.runloop.ai/docs/overview/your-runloop-trial)). #### Cua (trycua): hosted cloud ENDED; now bring-your-own-computer
- Banner on Cua's Nov 2025 launch post: "Cua Cloud (Fleets) ended on 18 October 2026"; cloud sandboxes, credit pricing and macOS waitlist no longer apply ([Cua blog](https://cua.ai/blog/cloud-windows-ga-macos-preview)).
- Historical (pre-shutdown) cloud Windows 11 sizes: Small 2 cores / 8 GB 8 credits/h; Medium 4 / 16 GB 15 credits/h; Large 8 / 32 GB 31 credits/h; under 1 s hot-start; noVNC over HTTPS; 4 regions; cloud macOS preview on bare-metal M1/M2/M4 ([Cua blog](https://cua.ai/blog/cloud-windows-ga-macos-preview)). As read 10 Oct 2026: Linux amd64 cloud on gVisor or KubeVirt, $0.044625/vCPU-hr + $0.0223125/GiB-hr, no suspend ([Simular](https://www.simular.ai/alternatives/cloud-computers-for-ai-agents)).
- Current product "Cua Spaces": "You bring the computers; Cua doesn't rent them"; Free $0 (2 computers in use, 20 remote hours/mo), Pro $15/mo yearly (5 computers, 200 h), Teams $25/seat/mo yearly ([Cua pricing](https://cua.ai/pricing)). Mac (Lume VMs), Linux (Docker/Podman containers), Windows preview; streaming over QUIC via a Cua-hosted relay that terminates TLS; Cua MCP server for Claude Code, Codex, Cursor, etc. ([Cua sandboxes page](https://cua.ai/sandboxes)).

#### Defunct or removed desktop offerings
- Scrapybara shut down its virtual desktop and browser service on 15 Oct 2025; Kernel merged a Scrapybara migration guide on 3 Oct 2025 ([Kernel docs PR #64](https://gh.r-mj.com/kernel/docs/pull/64); [DEV Community](https://dev.to/saptadev27/cloud-computers-for-ai-agents-in-2026-a-practical-comparison-5dbd)).
- Cloudflare Sandbox SDK desktop feature ("full Linux desktop" for UI automation) was removed for low adoption, with users pointed to Cloudflare Browser Run; Cloudflare says removal was in 0.10.2 ([Cloudflare 2026 deprecation guide](https://developers.cloudflare.com/sandbox/guides/2026-deprecation/); [Cloudflare changelog 9 Jun 2026](https://developers.cloudflare.com/changelog/post/2026-06-09-deprecating-sandbox-sdk-features/)); contradicted on version by [DEV Community](https://dev.to/saptadev27/cloud-computers-for-ai-agents-in-2026-a-practical-comparison-5dbd), which says 0.12.0. Sandbox SDK 0.x gets fixes until 2026-12-31.
- Bytebot (open-source self-hosted desktop agent) repo archived 7 Mar 2026 ([Bytebot GitHub](https://github.com/bytebot-ai/bytebot)); YC listing status is contradictory (Acquired vs Active) ([YC Bytebot](https://www.ycombinator.com/companies/bytebot)).

### Inferences
- For a developer wanting many hosted desktops via API with per-second billing, the realistic shortlist in Nov 2026 is E2B Desktop, Daytona, and Orgo; Windows 365 for Agents is the only hyperscaler full Windows desktop pool, and AgentBay the only one with Android in the same product.
- Linux desktops are commoditized around Xvfb/XFCE/VNC/noVNC; differentiation is in snapshot/pause semantics, concurrency limits, and accessibility-tree APIs (Daytona) rather than the desktop itself.
- macOS remains scarce and capacity-constrained in hosted form (Orgo "when in stock", Daytona macOS sandboxes, Cua's preview closed).
- The exits of Scrapybara and Cua Cloud suggest dedicated desktop-only hosting is hard to sustain against general sandbox vendors that add desktops as a feature.

### Gaps
- E2B per-sandbox metrics/logging API for desktops was not verified in this session.
- Exact semantics of Daytona Windows/macOS pricing (additive or replacement) and Windows boot time not found.
- Orgo virtualization technology and measured boot time not published (only a homepage claim of under 500 ms).
- Runloop Computer add-on pricing and current status could not be confirmed (404).
- AgentBay USD pricing, default concurrency, and Linux desktop support not confirmed.
- Simular box and InstaVM concurrency limits not found.

## Q2. What do the hyperscalers and model vendors (Microsoft, AWS, Google, OpenAI, Anthropic) offer for hosted agent computers?

### Takeaway
Microsoft is the only hyperscaler with a GA hosted full Windows desktop pool for agents (Windows 365 for Agents). AWS AgentCore Browser and Google's Computer Use sandbox are browser-centric (AWS added OS-level mouse/keyboard/full-desktop screenshots in April 2026 but the environment is still a managed browser). OpenAI offers an OpenAI-hosted browser only through its beta Agents API and otherwise points developers to Browserbase, Browser Use, Daytona and E2B. Anthropic's Managed Agents does not support computer use.

### Cited Findings

#### Microsoft Windows 365 for Agents
- Status: public preview announced at Ignite Nov 2025 ([Petri](https://petri.com/windows-365-for-agents-ai-cloud-pcs-preview/)); GA in week of 1 June 2026 ([Microsoft Learn what's new](https://learn.microsoft.com/windows-365/agents/whats-new)). Build 2026 post says Project Opal is powered by it ([Microsoft Tech Community, Build 2026](https://techcommunity.microsoft.com/blog/windows-itpro-blog/made-for-developers-and-agents-windows-365-at-build-2026/4519041)).
- Model: Cloud PCs grouped in provisioning policies / agent pools; agents check out and check in Cloud PCs; Intune-managed, Entra-governed; lifecycle, session control and UI automation via platform APIs; "session logs, observability tools, and human-in-the-loop controls"; powers Copilot Studio computer use, Project Opal, Researcher Computer Use (on Linux Cloud PCs) and Agent 365 ([Microsoft Learn intro, updated 18 Aug 2026](https://learn.microsoft.com/en-us/windows-365/agents/introduction-windows-365-for-agents)).
- Pricing (US): $0.40/hour pay-as-you-go, usage within each hourly window rounded up to the next full hour; always-available Cloud PCs add $5 per Cloud PC per month; varies by geography ([Microsoft Learn pricing](https://learn.microsoft.com/en-us/windows-365/agents/pricing-paygo-always-available)).
- Session semantics: phases Prepare/Acquire/Connect/Act/Release; agent channel via MCP; no maximum session duration; evicted after 30 minutes without an MCP request (heartbeat with `get_screen_size`); Cloud PC is reset on release so in-session state is lost; humans can observe and take over in the same session; unhealthy Cloud PCs quarantined and replaced ([Microsoft Learn session lifecycle](https://learn.microsoft.com/en-us/windows-365/agents/agent-session-lifecycle)).
- Pools defined by billing plan, region, count and image; created via Intune or Cloud PC Graph APIs; status evaluated at pool level, not per Cloud PC; Cloud PCs for Agents are reset after use (not persistent) and accessed via APIs ([Microsoft Learn agent pools](https://learn.microsoft.com/en-us/windows-365/agents/cloud-pc-agent-pools)).
- Related but not hosted: Microsoft MXC, an OS-level sandbox SDK for agents on Windows, announced 2 Jun 2026 ([VentureBeat](https://venturebeat.com/security/microsoft-launches-mxc-an-os-level-sandbox-for-ai-agents-with-openai-and-nvidia-already-on-board)). Azure OpenAI's computer-use-preview model accepts environment values browser/mac/windows/ubuntu, but the developer supplies the machine ([Azure OpenAI computer use docs](https://learn.microsoft.com/azure/ai-foundry/openai/how-to/computer-use)).

#### AWS Bedrock AgentCore Browser and Code Interpreter
- Pricing (both tools): $0.0895 per vCPU-hour and $0.00945 per GB-hour, per-second billing on actual CPU and peak memory, 1 s minimum, 128 MB memory minimum; I/O wait and idle time not charged for CPU; worked example: 10-minute browser session about $0.0123 ([AgentCore pricing](https://aws.amazon.com/bedrock/agentcore/pricing/)).
- Browser quotas: 1,000 concurrent active sessions per account (adjustable via support); hardware fixed at 1 vCPU / 4 GB per session (not adjustable); 1 automation stream and 1 live-view stream per session; 10 GB disk; async command max 8 h; up to 10 extensions; 100 profiles of 50 MB ([AgentCore quotas](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html)).
- Session timeout: default 3,600 s, max 28,800 s (8 h) ([StartBrowserSession API](https://docs.aws.amazon.com/bedrock-agentcore/latest/APIReference/API_StartBrowserSession.html)); live view is a WebSocket-based stream; recordings to S3 ([AgentCore browser session management](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/browser-managing-sessions.html)).
- OS-level actions launched 8 Apr 2026: mouse click/move/drag/scroll, keyboard typing and up to 5-key shortcuts, full-desktop screenshots (base64 PNG) beyond the viewport, to handle JS alerts, print dialogs and native context menus that CDP cannot ([AWS What's New, Apr 2026](https://aws.amazon.com/about-aws/whats-new/2026/04/agentcore-browser-os-actions); [AWS ML blog](https://aws.amazon.com/blogs/machine-learning/introducing-os-level-actions-in-amazon-bedrock-agentcore-browser/)).
- AgentCore Runtime (agent hosting, not GUI) allows 5,000 active sessions per account in us-east-1/us-west-2, up to 8 vCPU / 32 GB per session ([AgentCore quotas](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/bedrock-agentcore-limits.html)).

#### Google (Gemini Enterprise Agent Platform, formerly Vertex AI)
- Computer Use sandbox: "a secure, isolated browser environment" in a container; CDP (Playwright) access; navigate/click-at-coordinates/type/screenshot API; VNC live streaming view (noVNC over WebSocket); VPC-SC and CMEK supported ([Google Computer Use sandbox docs](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/sandbox/computer-use)). In Preview, "latency is optimized for low traffic volumes" ([Google quickstart, via search](https://docs.cloud.google.com/gemini-enterprise-agent-platform/scale/sandbox/computer-use-quickstart)).
- Code Execution sandbox: no network access, state kept up to 14 days (configurable TTL), us-central1 only (possibly outdated) ([Agent Engine Code Execution](https://docs.cloud.google.com/agent-builder/agent-engine/code-execution/overview)).
- Computer use is now native in Gemini 3.5 Flash for browser, mobile and desktop agents ([Google blog](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-computer-use-gemini-3-5-flash/)); the open-source kubernetes-sigs Agent Sandbox offers VNC desktops but is not a Google-hosted service ([Agent Sandbox docs](https://agent-sandbox.sigs.k8s.io/docs/use-cases/computer-use/)).

#### OpenAI
- Responses API computer tool: "You provide the environment and execute the model's requests"; recommended hosted environments: Browserbase, Browser Use (Cloud), Daytona (desktop sandbox), E2B Desktop; "A hosted environment may charge separately"; current examples use gpt-6-astra / gpt-6.2-sol and include a migration path from `computer-use-preview` ([OpenAI computer use guide](https://developers.openai.com/api/docs/guides/tools-computer-use)).
- Agents API (beta, `OpenAI-Beta: agents=v1`) offers an `openai_hosted` environment with `desktop.enabled` and screenshots; requires approval per new website origin; supports email/password/code sign-in (no passkeys/QR); no published pricing, concurrency or session limits ([OpenAI Agents API computer use](https://developers.openai.com/api/docs/guides/agents-api/tools/computer-use)). Third-party coverage dated 29 Sep 2026 describes it as a hosted browser ([Digital Applied](https://www.digitalapplied.com/blog/openai-agents-api-computer-use-hosted-browser)).
- Hosted shell containers for the Responses API (engineering post 11 Mar 2026) are terminal-only workspaces ([OpenAI](https://openai.com/index/equip-responses-api-computer-environment); [OpenAI shell tool docs](https://developers.openai.com/api/docs/guides/tools-shell.md)). Codex shipped local Computer Use on Windows on 29 May 2026 (third-party report) ([Codex blog, D. Vaughan](https://codex.danielvaughan.com/2026/06/04/codex-computer-use-windows-foreground-desktop-automation-agent-sandbox-permissions/)).

#### Anthropic
- Computer use tool is client-side and needs your own sandboxed environment; it is not currently available in Claude Managed Agents ([Claude computer use docs](https://platform.claude.com/docs/en/agents-and-tools/computer-use)).
- Managed Agents provides shell and file tools in an Anthropic-managed or self-hosted sandbox (self-hosted via Cloudflare, Daytona, Modal or Vercel) ([Claude Managed Agents updates](https://claude.com/blog/claude-managed-agents-updates)); browser work via a Browserbase integration ([Browserbase docs, Managed Agents](https://docs.browserbase.com/integrations/anthropic/managed-agents/introduction.md)).

### Inferences
- Model vendors have chosen to partner rather than host desktops: OpenAI and Anthropic both route desktop computer use to Daytona/E2B and browser use to Browserbase/Browser Use.
- Windows 365 for Agents is designed for enterprise IT (Intune, Entra, pools reset after each task) and is billed in whole hours, which is costly for many short tasks and unsuitable for persistent per-agent machines.
- AgentCore's fixed 1 vCPU / 4 GB per session and single live-view stream show it is optimized for many light browser sessions, not heavy desktop apps.

### Gaps
- Whether third-party developers outside Copilot Studio / Agent 365 can self-serve Windows 365 for Agents pools via public APIs at scale, and per-tenant pool size limits, were not documented in the pages read.
- Pricing and limits for Google's Computer Use sandbox and OpenAI's hosted browser were not published.
- AgentCore CloudWatch per-session metrics and live-view protocol details (DCV or other) were not confirmed.

## Q3. Which platforms are browser-only, and how does that limit computer use?

### Takeaway
Browserbase, Steel, Hyperbrowser, Kernel, Anchor, Browser Use Cloud, Cloudflare Browser Run, AWS AgentCore Browser and Google's Computer Use sandbox are browser infrastructure. Kernel and AgentCore partially close the gap with OS-level mouse/keyboard/screenshot controls on the browser VM.

## Q5. How well does each platform support running MANY concurrent desktop machines with management APIs and per-machine monitoring/visibility?

### Takeaway
Concurrency is plentiful on paper (E2B up to 1,100+, Daytona pooled up to 500 vCPU self-serve, Orgo up to 999, AgentCore 1,000, Kernel 500, Windows 365 pool-sized), and every vendor exposes lifecycle APIs. Per-machine visibility is uneven: live view is almost always one stream per session, and documented fleet-level views are rare. Windows 365 reports status at the pool level, not per Cloud PC. No source described a multi-desktop "wall" dashboard with per-machine metrics for desktop fleets.

### Cited Findings
- E2B: Pro 100 concurrent, add-ons to 1,100, Enterprise 1,100+; creation 1/s (Hobby) or 5/s (Pro) ([E2B billing docs](https://docs.e2b.dev/billing)); one desktop stream at a time per sandbox ([e2b-dev/desktop](https://github.com/e2b-dev/desktop)).

- Browserbase: up to 250+ concurrent on Scale; Session Inspector exposes network, console, performance and resource usage per session ([Browserbase pricing](https://www.browserbase.com/pricing); [Browserbase docs](https://docs.browserbase.com/fundamentals/using-browser-session)).

### Inferences
- The observability gap is biggest on desktop platforms: browser vendors offer inspectors, replays and telemetry per session, while desktop vendors mostly offer a single VNC/noVNC stream per machine plus optional recording (Daytona) and leave fleet dashboards to the customer.
- Concurrency limits are usually expressed as resource pools or rate limits (vCPU, creations/min, control calls/min) rather than "N desktops", so planning a 100+ desktop fleet requires converting desktop sizes into each vendor's pool math.
- Windows 365 for Agents' pool-level health model and reset-after-use semantics favor stateless batch tasks over long-lived, individually monitored agent machines.

### Gaps
- No vendor documentation found for a built-in multi-machine live grid view (watch many desktops at once) or per-machine CPU/memory metrics for desktop sandboxes; this may exist in consoles not covered by public docs.
- E2B dashboard and metrics capabilities for desktop fleets were not verified.
