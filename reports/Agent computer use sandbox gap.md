# Build the open desktop fleet nobody ships

**The gap is real, but it is narrower and more specific than "there are no good platforms."** As of late November 2026, hosted Linux sandboxes are crowded (E2B, Daytona, Modal, Orgo and several new YC companies in every batch), hosted browsers are cheap and well instrumented, and Microsoft and AWS now sell governed Windows desktops to enterprises. What nobody ships is an open-source, self-hostable layer that puts lightweight microVM lifecycle, a maintained desktop image, an MCP control surface and fleet-wide visibility (live views, per-machine metrics, recordings) into one product. That slot widened during 2026: Daytona went closed source, Cua shut down its cloud fleets, Bytebot was archived and Cloudflare dropped its desktop feature. Your "not that big" thesis holds for the core loop. One Linux desktop in a Firecracker microVM, driven over MCP, is a weeks-scale project, and several open projects already show it working. The thesis breaks on the full promise, because "whatever virtualization is available," "extremely lightweight" and "all modern computer use" pull against each other. Firecracker runs only on Linux KVM and has no GPU. Current Chromium no longer falls back to software WebGL by default. RAM, which got much more expensive in 2026, limits a 256 GB host to roughly 60 to 120 desktops before page sharing. Windows and macOS guests are licensing problems rather than engineering ones. And 2026 brought a host-kernel escape out of Firecracker plus three Firecracker CVEs. The product worth releasing is an Apache-2.0 single-binary daemon that turns any Linux KVM box into a fleet of disposable Linux desktops. It needs warm-snapshot create, fork and reset; an MCP server plus adapters for each model vendor's native computer-use tool; and a "glass wall" of live thumbnails with a timeline for every machine. Aim it first at eval, RL and agent-QA teams that need 50 to 300 desktops on hardware they control, and do not host compute.

## Hosted Linux sandboxes are crowded while open desktop fleets sit empty

The hosted market in November 2026 has three layers, and none of them is the thing you described. The first is general sandbox vendors that added desktops as a feature. **E2B Desktop** runs Ubuntu 22.04 with XFCE inside a Firecracker microVM and streams it over VNC ([E2B docs](https://docs.e2b.dev/use-cases/computer-use)). **Daytona** launches Xvfb, xfce4, x11vnc and noVNC on Linux or Windows sandboxes and adds accessibility-tree queries and screen recording ([Daytona docs](https://www.daytona.io/docs/en/computer-use/)). **Orgo** sells always-on Linux computers, charges $15 per month extra for Windows below its Scale plan, and offers Macs "when in stock" ([Orgo pricing](https://www.orgo.ai/pricing.md)). Newcomers keep arriving: Simular's box entered beta on 12 November ([Simular](https://www.simular.ai/articles/box-by-simular-the-computer-your-agents-needs)), and Phaze raised an $8.75M seed led by a16z on 4 November ([Utah Business](https://www.utahbusiness.com/press-releases/2026/11/04/phaze-raises-seed-led-a16z-give-ai-agents-access-computers-indie-nextview/)).

The second layer is browser infrastructure (Browserbase, Kernel, Steel, Hyperbrowser, AWS AgentCore Browser). It is cheaper and better instrumented, but it ends at the browser. AWS added OS-level mouse and keyboard control to AgentCore Browser in April 2026 because CDP cannot handle JS alerts, print dialogs or native context menus ([AWS ML blog](https://aws.amazon.com/blogs/machine-learning/introducing-os-level-actions-in-amazon-bedrock-agentcore-browser/)).

The third layer is enterprise desktops. **Windows 365 for Agents** went GA in the week of 1 June 2026 at **$0.40 per hour, rounded up to the full hour** ([Microsoft Learn](https://learn.microsoft.com/en-us/windows-365/agents/pricing-paygo-always-available)). It resets each Cloud PC when the agent releases it ([Microsoft Learn](https://learn.microsoft.com/en-us/windows-365/agents/agent-session-lifecycle)) and evaluates health per pool rather than per machine ([Microsoft Learn](https://learn.microsoft.com/en-us/windows-365/agents/cloud-pc-agent-pools)). AWS previewed agent access to WorkSpaces through a managed MCP endpoint in May ([The Register](https://www.theregister.com/2026/05/06/aws_workspaces_agent_access/)).

The model vendors chose to partner instead of hosting. OpenAI's guide says "You provide the environment" and names Browserbase, Browser Use, Daytona and E2B ([OpenAI](https://developers.openai.com/api/docs/guides/tools-computer-use)). Anthropic's computer-use tool runs client-side and is not available in Claude Managed Agents ([Claude docs](https://platform.claude.com/docs/en/agents-and-tools/computer-use)).

The exits matter as much as the entrants. Scrapybara shut its virtual desktop service on 15 October 2025 ([DEV Community](https://dev.to/saptadev27/cloud-computers-for-ai-agents-in-2026-a-practical-comparison-5dbd)). Cloudflare removed the desktop from its Sandbox SDK for low adoption ([Cloudflare](https://developers.cloudflare.com/sandbox/guides/2026-deprecation/)). Daytona moved core development to a private codebase in June 2026 ([Daytona](https://www.daytona.io/dotfiles/updates/daytona-is-going-closed-source)). **Cua Cloud, including Fleets, ended on 18 October 2026** ([Cua](https://cua.ai/blog/cloud-windows-ga-macos-preview)). Bytebot's repository is archived ([GitHub](https://github.com/bytebot-ai/bytebot)). Firecracker-containerd stopped being maintained on 10 November 2026, and firecracker-go-sdk is archived too ([firecracker-containerd](https://github.com/firecracker-microvm/firecracker-containerd)). Two patterns stand out: desktop-only hosting struggles against general sandbox vendors that bolt desktops on, and open source is retreating at the infrastructure layer.

Visibility is where the hosted offerings are thinnest. E2B's desktop SDK states "There can be only one stream at a time" ([e2b-dev/desktop](https://github.com/e2b-dev/desktop)). Windows 365 for Agents reports status per pool, and Daytona offers a recording dashboard. Browser vendors go further: Browserbase exposes a per-session inspector with network, console, performance and replay ([Browserbase docs](https://docs.browserbase.com/fundamentals/using-browser-session)). None of the public documentation reviewed describes a live wall of many desktops with per-machine metrics. That is an absence in public docs, and vendor consoles can hold more than their docs describe, but it matches what builders ask for.

The open-source layer has strong parts and no assembled whole. **E2B's runtime** (Apache-2.0) is the most complete open Firecracker control plane. Templates are pre-booted snapshots, memory is served lazily through userfaultfd, the root filesystem is a copy-on-write overlay, idle sandboxes auto-pause, a live sandbox can fork into up to 100 copies, and "E2B Embed" runs the whole thing on a single KVM host ([e2b-dev/runtime](https://github.com/e2b-dev/runtime)). It is Linux-only, and its desktop gets a single stream. **OpenSandbox** (Apache-2.0, 18.0k stars) offers a Firecracker "Fast Sandbox" with 64 ms P50 creation, an MCP server for create, exec and file operations, and desktop examples ([OpenSandbox](https://github.com/opensandbox-group/OpenSandbox)). A downstream project found, though, that pausing a desktop microVM there writes a full disk-and-memory checkpoint that takes **about three minutes** ([openwork PR #6726](https://github.com/different-ai/openwork/pull/6726)). **Arrakis** is the closest single-repo match (Cloud Hypervisor, VNC plus Chrome, MCP, snapshot restore), but it is AGPL and has not been pushed since June 2025 ([Arrakis](https://github.com/abshkbh/arrakis)). The rest are partial pieces. Kubernetes-sigs/agent-sandbox provides warm pools with no desktop or streaming ([agent-sandbox](https://github.com/kubernetes-sigs/agent-sandbox)). The libkrun family (microsandbox, smolvm, BoxLite) are embeddable runtimes without fleet dashboards ([smolvm](https://github.com/smol-machines/smolvm)). neko, Selkies and KasmVNC handle streaming ([neko](https://github.com/m1k1o/neko)). Nobody has combined lifecycle, desktop, MCP, a live view of many machines and recording into one self-hostable product.

## Builders who complain about platforms keep becoming vendors

The exact sentence "there are no good platforms for running a lot of sandboxed computers" never turned up. Reddit and X post bodies could not be read, so where it came from is unknown. The sentiment itself is common in 2026, and it usually comes from people who then built their own platform. Coasty's co-founder said the existing options "are either expensive, capped at 24-hour sessions, or both" ([HN](https://news.ycombinator.com/item?id=47268583)). A solo builder said vendors added "like a 50x markup on what qemu/docker + bare metal prices would be," then released his own box ([HN](https://news.ycombinator.com/item?id=48907563)). Another commenter wanted "a one click sandbox agent on a self hosted instance that is, free, fast ... and that is open source," with "no rug pulls" ([HN](https://news.ycombinator.com/item?id=48688995)). Replies to an Ask HN on why everyone rolls their own pointed to "no de facto standard yet" ([HN](https://news.ycombinator.com/item?id=46699324)). A September comment summed it up: "Don't think we've had the 'Docker moment' for this" ([HN](https://news.ycombinator.com/item?id=49822295)).

The specific complaints line up with your plan unevenly.

- **Caps and cost are well documented.** E2B Hobby allows 10 concurrent sandboxes with 1-hour sessions, and Pro allows 100 with 24 hours ([E2B billing](https://docs.e2b.dev/billing)). One founder called Daytona's credits "close to useless given their restrictions until you hit tier 3" ([HN](https://news.ycombinator.com/item?id=50059096)).
- **Windows is the loudest OS gap.** Asked whether E2B Desktop supports Windows, a maintainer replied "no way, because we roll em' Firecrackers, and they don't mess with Windows" ([GitHub](https://github.com/e2b-dev/desktop/issues/112)).
- **macOS is capped at two VMs per Mac by Apple's license.** Cua's founder cited this limit again when he launched the closed-source Hoy VMM in November 2026 ([HN](https://news.ycombinator.com/item?id=50534225)).
- **RL reset and fork is a measurable win.** The CUA-Sandbox paper reports up to **6.20x rollout throughput and 9.2x lower memory per environment** from sharing runtimes and branching state ([arXiv](https://arxiv.org/abs/2609.32750)).
- **Observability demand comes mostly from regulated buyers.** One HIPAA-regulated prospect asked whether screenshots, playback and logs are "stored on our infra or yours" ([HN](https://news.ycombinator.com/item?id=48922706)).

Two loud complaints are out of reach for any infrastructure product: browser-provider flakiness, and especially anti-bot and identity walls. In one builder's words, "Rendering was almost never the blocker. Identity was." ([HN](https://news.ycombinator.com/item?id=49214403)).

Eval and RL is the segment where "a lot of computers" literally means hundreds. The OSWorld maintainer advises a parallelism of about 300 to finish an evaluation within an hour ([OSWorld #374](https://github.com/xlang-ai/OSWorld/issues/374)). One researcher hit `VcpuLimitExceeded` running just five parallel environments on AWS ([OSWorld #366](https://github.com/xlang-ai/OSWorld/issues/366)). The CUA-Lite authors complain that "evaluation, RL, and SFT cannot share one infrastructure" ([arXiv](https://arxiv.org/abs/2610.26071)). Big labs build their own, so the teams short on quota and money are academic groups, smaller labs and RL-environment vendors. Other segments want different things. Agent startups automating legacy software and QA want Windows, replay and compliance. Enterprises are being served top-down by Microsoft and AWS. A long tail of developers want a safe GUI box for coding agents: "I run it in a VM using a headless wayland compositor, I'd never trust even fable with access to my real system" ([HN](https://news.ycombinator.com/item?id=48662999)).

The counter-evidence matters just as much. On Agent37's launch, one commenter wrote "You cannot 10x on basically what's just a VM with a few agent-friendly features in 2026," and another compared YC batches full of sandbox companies to "hunger games" ([HN](https://news.ycombinator.com/item?id=50059096)). Cloudflare's desktop died of low adoption. OpenAI now recommends code execution for GPT-6 Astra and calls the computer tool "supported as an alternative" ([OpenAI](https://developers.openai.com/api/docs/guides/tools-computer-use)). The money is real but mostly sits elsewhere. Modal raised $750M at a $15.75B valuation, with "nearly one-third" of a run rate above $1B coming from Sandboxes ([SiliconANGLE](https://siliconangle.com/?p=850503)). Daytona reportedly raised $60M at a $1B valuation, though an SEC-filing-based report gives $48.3M ([Fortune](https://fortune.com/2026/10/20/daytona-startup-building-the-agentic-cloud-valued-at-1-billion-in-latest-funding-round/); [Dealroom](https://dealroom.co/news/145417-daytona-lands-48-3m-series-b-for-ai-agent-sandbox-platform/)). Both companies grew mainly on coding and Linux workloads. So the gap is one of fit (desktop-first, self-hosted, observable, resettable), not a shortage of vendors. Appetite for open source is clear from star counts: trycua/cua reached 33k stars in about 22 months, and Tencent's CubeSandbox reached 13.5k in about seven ([GitHub](https://github.com/trycua/cua); [GitHub](https://github.com/TencentCloud/CubeSandbox)). There is also a steady run of self-hosted sandbox Show HNs, including Screenbox's self-hosted virtual desktops ([HN](https://news.ycombinator.com/item?id=47617846)). Stars measure interest, not production deployments.

## The demo takes weeks, but the three promises collide

You have the stack right. Every serious agent desktop uses the same recipe: a VM, Xvfb, a light window manager, xdotool, x11vnc with noVNC, and a browser. E2B's template follows it ([E2B template](https://github.com/e2b-dev/desktop/blob/main/template/template.py)), and so does Anthropic's reference container ([Anthropic Dockerfile](https://github.com/anthropics/claude-quickstarts/blob/main/computer-use-demo/Dockerfile)). Firecracker reaches guest init in **at most 125 ms with at most 5 MiB of VMM memory overhead** ([Firecracker spec](https://github.com/firecracker-microvm/firecracker/blob/main/SPECIFICATION.md)). Booting one desktop under MCP control is a small project, and Arrakis, E2B Desktop and Anthropic's demo have already done it. The trouble starts when the design has to keep all three of your promises at once.

Both exceed the roughly $0.05 to $0.10/hour of compute for the desktop itself. | Never stream every machine. Pull thumbnails, and open video only for the tile a human is focused on. |

The graphics row is where "extremely lightweight" and "all modern computer use" collide head-on. Lightweight VMMs get their speed by having no device model for displays or GPUs, so every frame is rendered in software on guest vCPUs. Until recently that was tolerable because Chromium quietly fell back to SwiftShader. Now WebGL context creation fails by default without a GPU, and the escape hatch is explicitly flagged as unsafe for the kind of untrusted content agents browse. The practical answer has three parts: ship Firefox (which still accepts llvmpipe) as the default browser, document the WebGL and video limits honestly, and treat GPU desktops as a separate, later tier on a heavier VMM.

The density row overturns the intuition behind "extremely lightweight." Firecracker's 5 MiB overhead is about 0.1% of a 4 GiB desktop. Even the roughly 180 MiB QEMU footprint measured under Kata ([computingforgeeks](https://computingforgeeks.com/gvisor-vs-kata-containers-vs-runc/)) is under 5%. The VMM choice barely moves density. What does move it is restoring every desktop from one warm snapshot so that read-only pages stay shared. One vendor measured a restored guest at **about 1.45 GiB of shared clean pages against 72 MiB of private dirty pages** ([PandaStack](https://www.pandastack.ai/blog/firecracker-ksm-memory-deduplication-explained/)). Browsing dirties pages quickly, so the real marginal cost of an active desktop falls somewhere between those two figures, and no public benchmark measures it. "Lightweight" should mean light to operate (one binary, one box, fast warm starts), not a small VMM.

Snapshots and security are tangled together. The features that raise density, snapshot restore combined with memory ballooning or virtio-mem, are exactly where CVE-2026-122192 sat, and Firecracker's advisory lists the userfaultfd memory backend as a workaround ([GHSA](https://github.com/firecracker-microvm/firecracker/security/advisories/GHSA-48ww-rqpp-2mgm)). KSM page merging across tenants is a known timing side channel ([PandaStack](https://www.pandastack.ai/blog/firecracker-ksm-memory-deduplication-explained/)). The PwnEscape chain ran Firecracker without the jailer, as root, and fixing it required patching and rebooting the host kernel ([iTnews](https://www.itnews.com.au/news/researchers-turn-pwnescape-linux-flaw-into-firecracker-breakout-630201)). A self-hosted fleet product inherits all of these duties. Its defaults and preflight checks decide whether its users' machines are safe.

| Tier | Scope | Existing proof | Honest effort (my estimate) |
|---|---|---|---|
| Demo | One Linux desktop microVM with VNC, xdotool and a handful of MCP tools | Arrakis, E2B Desktop template, Anthropic demo | One to three weeks for one strong developer |
| Product | Warm-snapshot create, pause, fork and reset; glass wall; timelines and recordings; native tool adapters; secure defaults; one host running 50 to 300 desktops | Pieces in E2B runtime, neko, Firecracker docs | Two to four months solo to a credible v0.1, then ongoing maintenance |
| Platform | Multi-host scheduling, Windows and macOS guests, a GPU tier, and a hosted service with abuse controls and compliance | E2B, Daytona, Modal. Manus estimated that building sandbox infra in-house would need 3 to 5 full-time infra engineers ([E2B blog](https://e2b.dev/blog/how-manus-uses-e2b-to-provide-agents-with-virtual-computers)) | Team-years and venture capital |

"Not that big" is true for the demo, and it holds for the product as long as the product is scoped to Linux guests on Linux KVM hosts. It is false for the platform, and the platform is what "whatever host, all modern computer use" implies. The good news is that the open gap sits squarely in the product tier.

## Bare-metal economics reward shipping software, not renting computers

At E2B and Daytona's published rates ($0.0504 per vCPU-hour and $0.0162 per GiB-hour), a 2 vCPU, 4 GiB desktop costs about **$0.166 per hour** ([Daytona pricing](https://www.daytona.io/pricing)). On AWS, a c7i.metal-48xl costs $8.568 per hour on demand ([Vantage](https://instances.vantage.sh/aws/ec2/c7i.metal-48xl)). Packing 90 desktops at 4 GiB onto it gives about $0.095 per desktop-hour at full occupancy, so a hosted business on AWS breaks even at roughly 57% average occupancy, before egress, storage, abuse and staff. On Hetzner, an AX162-R costs EUR 242.30 per month after the April 2026 increase ([webhosting.today](https://webhosting.today/2026/05/29/hetzner-has-now-raised-prices-three-times-in-2026-this-one-is-different/)). If it holds about 60 desktops, that is roughly EUR 0.0055 per desktop-hour, though its exact RAM spec was not verified. The "50x markup" complaint is therefore roughly right measured against rented bare metal and wrong measured against AWS. Vendors mark up hyperscaler metal by under 2x. The rest of the gap is the hyperscaler premium plus the occupancy risk vendors carry. The savings live on bare metal the customer controls, which argues for selling software rather than computers.

Infrastructure is not what dominates a computer-use bill, either. Each Claude screenshot costs about 1,000 to 1,800 input tokens ([Claude docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)). At one screenshot every five seconds, that is roughly 0.7 to 1.3 million image tokens per session-hour: dollars per hour against cents per hour of desktop compute. Teams calling frontier APIs therefore choose on reliability, visibility, compliance and the absence of caps, not on desktop-hour price. Price matters most to RL and eval groups running their own models at high parallelism, which is exactly the wedge segment.

Hosting also brings problems a solo developer should not take on. Free compute attracts crypto miners, botnets and phishing. Heroku ended its free plans citing fraud and abuse ([TechCrunch](https://techcrunch.com/2022/08/25/heroku-announces-plans-to-eliminate-free-plans-blaming-fraud-and-abuse)), Koyeb required a payment method from everyone after an "exponential surge of abuse" ([Koyeb](https://koyeb.com/blog/sustaining-free-compute-in-a-hostile-environment)), and Modal built syscall-level miner detection ([Modal](https://modal.com/blog/catching-cryptominers)). A self-hosted open-source product avoids abuse entirely, because users bring their own hardware. It also answers the HIPAA question ("stored on our infra or yours?") by construction, because it never touches the data path, unlike Cua's relay, which terminates TLS ([Cua](https://cua.ai/sandboxes)).

The Apache-2.0 license is a positioning choice. It contrasts with Daytona's closure, Cua's FSL components and Arrakis's AGPL, and it is the license lab and enterprise legal teams approve fastest. Revenue can come later, from support contracts and from the features organizations pay for: SSO, RBAC, audit retention, multi-host scheduling and Windows bring-your-own-license backends.

## Seven risks, and the hedge for each

| Risk | Evidence | Hedge |
|---|---|---|
| An incumbent ships the same visibility layer | E2B's runtime is open and already includes a web dashboard for builds and killed sandboxes ([E2B architecture](https://github.com/e2b-dev/runtime/blob/main/docs/ARCHITECTURE.md)); OpenSandbox has 18k stars, Firecracker and MCP | Win on desktop depth (warm desktop snapshots, timelines, takeover), ship fast, and keep the console backend-agnostic so it can later drive E2B or OpenSandbox hosts too |
| GUI desktop demand is smaller than the hype | Cloudflare's desktop died of low adoption; Scrapybara and Cua Cloud exited; OpenAI steers GPT-6 Astra toward code execution | Target segments where a desktop is mandatory (eval and RL, QA of legacy apps), and offer a cheap headless-browser profile in the same fleet |
| The capability ceiling disappoints users | WebGL fails by default in GPU-less Chromium; Windows-only apps need Windows | State the limits in the README, default to Firefox, and put GPU and Windows backends on a public roadmap |
| A security incident on a user's fleet | PwnEscape was found with AI for under $700 in tokens; three Firecracker CVEs in 2026 | Jailer always on, userfaultfd memory backend, no cross-VM KSM, preflight checks on the host kernel, and a published advisory process |
| The maintainer burns out with no revenue | Bytebot archived, Arrakis stale since mid-2025, Daytona closed | Sign two or three design partners before v0.1, and sell support contracts by v0.3 |
| Model and protocol churn | Stale Anthropic toolset versions get HTTP 400; MCP changed its core model in July 2026 | Keep adapters thin and run conformance tests per vendor in CI |
| Hardware costs keep rising | DRAM up 43% to 48% in Q4 2025; Hetzner raised prices three times in 2026 | Make density the headline benchmark and pause idle desktops to disk aggressively |

## Conclusion

The scarce resource in agent computer use is not virtual machines; it is the ability to see and steer hundreds of them. The VMs are a commodity at nine-figure scale, and the people who complain loudest about platforms keep becoming platforms. Visibility (a wall of desktops, a timeline for every step, human takeover) is the piece nobody ships in the open, and it is also the piece that sells itself in a demo. "Lightweight" has been mis-specified, too. VMM overhead is a rounding error next to a browser's memory, so the lightness that matters is operational: one binary, one box, warm snapshots and no Kubernetes.

The 2026 exits suggest the business is open source plus enterprise features and support, not hosted compute. Your strongest launch asset is something nobody has published: a public, reproducible benchmark of how many desktop microVMs fit on one box. The research found no such benchmark, and that number is the first thing every self-hoster and RL team will want to know.

## Recommendation: ship a single-binary Linux desktop fleet with a glass wall

Build an open-source (Apache-2.0) daemon, working name "deskfleet" (a placeholder), that turns any Linux host with `/dev/kvm` into a fleet of disposable Linux desktop microVMs. Machines are created, forked, reset and destroyed over REST, MCP and SDKs, and a web console shows every one of them live. Target eval, RL and agent-QA teams that need 50 to 300 desktops on hardware they control. Use individual developers who want a safe GUI box for Claude Code or Cursor as the adoption on-ramp. Against each competitor, the one-line pitch is:

- **E2B:** the same snapshot model, but desktop-first and in one binary.
- **Daytona:** the same computer-use API, but open.
- **Orgo:** the same live desktops, but on your own hardware.
- **Windows 365 for Agents:** session logs per machine and billing per second, instead of per pool and per hour.
- **OpenSandbox:** the same lifecycle, plus the desktop and the glass wall.

### MVP feature list (v0.1)

| Feature | Scope in v0.1 | Why it earns a place |
|---|---|---|
| One-command install with preflight | A single static binary that checks `/dev/kvm`, nested-virtualization status, the host kernel version against known escapes, and the Firecracker version | The "Docker moment" builders say is missing, plus safe-by-default hosts |
| Desktop template | Minimal Debian or Ubuntu with Xvfb at 1280x800, openbox and tint2, xdotool, Firefox ESR by default and Chromium optional, plus a small in-guest agent over vsock. Users can build custom templates from an OCI image or Dockerfile | Matches Anthropic's resolution guidance and keeps screenshot tokens low; Firefox avoids Chromium's WebGL failure |
| Warm-snapshot lifecycle | Create from a warm snapshot with the desktop and browser already running; pause and resume to local disk; fork into N copies; reset to snapshot; stop and destroy; TTL and idle auto-stop; labels | Sub-second starts and RL-grade reset and fork are what users complain are missing |
| Computer API | Screenshot sized to each model's limits; click, move, drag and scroll; type, key and hotkey; wait; exec; file upload and download; clipboard | Covers the union of the Anthropic, OpenAI and Gemini action sets |
| MCP server | Streamable HTTP plus stdio; lifecycle and computer tools; a high-entropy machine handle with a stated lifetime returned by `create_machine`, per the 2026-07-28 stateless model; the tasks extension for boot and snapshot; rate limiting | Lets any MCP client drive machines; follows spec guidance for stateful tools ([MCP](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)) |
| Native tool adapters (Python and TypeScript SDKs) | Execute Anthropic `computer_toolset_20260801` calls, OpenAI `computer` actions and Gemini normalized coordinates against a machine | Models are trained on their own tool schemas, so native adapters beat generic MCP tools on accuracy |
| Glass wall console | Thumbnails pulled at 0.5 to 2 fps for visible tiles only, reusing the agent's own screenshots; clicking a tile opens a live view (neko WebRTC, with noVNC as fallback) with input-locked takeover; per-machine CPU, RAM and network from cgroups | The visibility gap no product fills; the pull design keeps egress and encode cost near zero for idle machines |
| Per-machine timeline and recording | Every action logged with before and after screenshots, emitted as OpenTelemetry `execute_tool` spans tagged with the machine ID, joined via the `traceparent` field in MCP `_meta`; trajectory export as JSON; MP4 on demand | Audit and HIPAA questions, RL debugging; screenshot logs cost about 108 MB per session-hour (my estimate) instead of continuous video |
| Safe defaults | Jailer always on, seccomp, per-VM cgroup memory caps, userfaultfd memory backend, no KSM, default-deny egress with per-machine allowlists, SMTP blocked, scoped API tokens, no secrets inside guests | The 2026 CVEs and PwnEscape, plus Anthropic's own guidance to allowlist domains and keep logins away from the model |
| Published benchmark | Desktops per host, create latency, and memory per idle and per active desktop, measured on a reference Hetzner box and an AWS metal box | No public benchmark of desktop microVM density exists; it is your launch story |

### Architecture choices

| Layer | Choice | Why | Kept open for later |
|---|---|---|---|
| VMM | Firecracker 1.17.0 or newer (1.18.0 is current, released 9 Nov 2026 ([changelog](https://github.com/firecracker-microvm/firecracker/blob/main/CHANGELOG.md))), driven directly over its API socket | Proven for Linux desktops at E2B, millisecond-scale snapshot restore with lazy memory, small attack surface. The Go SDK is archived, so own the thin client | A Cloud Hypervisor backend for Windows guests and VFIO GPU, since it supports Windows 11 guests ([Cloud Hypervisor](https://github.com/cloud-hypervisor/cloud-hypervisor)); a libkrun backend for macOS laptops ([libkrun](https://github.com/libkrun/libkrun)); kernel/hypeman as a multi-hypervisor runtime worth evaluating ([hypeman](https://github.com/kernel/hypeman)) |
| Host target | Linux with `/dev/kvm`: bare metal (Hetzner, OVH, AWS .metal) for fleets, and nested-capable cloud VMs (AWS C8i/M8i/R8i, GCP, Azure Dv5) for trials | Choose backends by guest class, not by host OS; one backend keeps v0.1 small | On M3 or newer Macs, run inside a Linux VM with nested virtualization (best effort) |
| Control plane | One Go or Rust daemon with SQLite state, local NVMe for snapshots and an optional S3-compatible store | "Extremely lightweight" in the sense that matters: one process, one box | A small multi-host coordinator in v0.2; Kubernetes only via the existing agent-sandbox CRDs |
| Snapshot strategy | A warm template per image, restored copy-on-write with memory mapped privately so idle desktops share pages; diff snapshots for pause; no balloon or virtio-mem with the File memory backend | Page sharing is the density lever, and this avoids the CVE-2026-122192 path | virtio-mem hotplug once it has a clean security record |
| Display and input | X11 with Xvfb, xdotool and an in-guest agent over vsock for screenshots, input, exec and files | The most mature tooling, and it keeps working even when guest networking is locked down | A headless Wayland compositor (the Smithay-based one from Selkies and webtop) and an AT-SPI accessibility tree in v0.2 |
| Live view | neko (Apache-2.0), whose GStreamer pipeline starts only when a viewer connects ([neko](https://github.com/m1k1o/neko/blob/master/webpage/docs/configuration/capture.md)); noVNC as fallback | No encoder cost for unwatched machines; WebRTC is better for human takeover | An MCP Apps `ui://` view so supporting hosts can embed the live desktop ([MCP Apps](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/)) |
| Networking | One TAP device per VM, nftables default deny with allowlists, per-VM rate limits, and a host-side proxy for credential injection | Blocks prompt-injection exfiltration and abuse, and keeps secrets out of screenshots | Per-tenant egress IPs |
| Observability | OpenTelemetry GenAI spans, Prometheus metrics from cgroups, logs to stderr | MCP deprecated its Logging feature in favor of OpenTelemetry | Hooks for Honeycomb and Datadog |

### What not to build at first

| Do not build (yet) | Why |
|---|---|
| A hosted public cloud or free tier | Abuse, break-even at roughly 57% occupancy on AWS, competitors with $1B or larger valuations, and the exits of Scrapybara and Cua Cloud |
| macOS guests | Two per Mac, for development or testing only, with a 24-hour minimum for leased hosting |
| Hosted Windows | Windows 11 needs customer-owned Enterprise or VDA rights. Ship Windows later only as a bring-your-own-license backend on customer hardware |
| GPU desktops | Firecracker has no path to a GPU, so this needs a second VMM with passthrough and roughly doubles scope |
| A Kubernetes operator or multi-region scheduler | agent-sandbox already exists, and one well-packed host covers the 50 to 300 desktop wedge |
| Non-KVM fallbacks (QEMU TCG, gVisor) | TCG is 8x to 12x slower, and gVisor is not a VM |
| Memory ballooning, virtio-mem and cross-VM KSM | They sit on the 2026 CVE path and open a side channel, while snapshot page sharing delivers most of the gain |
| Continuous video for every machine, or MP4 recording by default | Egress and software-encode cost exceed the desktop's own compute |
| Anti-bot stealth, residential proxies, CAPTCHA solving | Browser vendors are fighting that battle, and it is an identity problem, not an infrastructure one |
| The agent loop, planners or prompt tooling | Outside your chosen scope, and plenty already exists |
| Android | Cuttlefish works on KVM later, but it is separate image and input work |

### Sequencing

| Release | Ships | Gate before moving on |
|---|---|---|
| v0.0 (internal, first three weeks) | Warm desktop template, Firecracker runner and benchmark harness | Measured memory per idle and per active desktop, and create latency on one reference box |
| v0.1 (public, about month three) | Everything in the MVP table | Two or three design partners running 50 or more desktops each |
| v0.2 | Multi-host coordinator, fork-at-step and reset API with an OSWorld-style harness adapter, accessibility tree, headless Wayland option, MCP Apps live view, macOS laptop backend via libkrun | Sustained weekly active installs and the first paid support contract |
| v0.3 | Windows guests on Cloud Hypervisor with customer-supplied licenses, a GPU tier, and paid SSO, RBAC and audit retention | Decide on open core versus a support-only model |

Start with the benchmark, not the console. Build the warm-snapshot desktop and measure how many idle and active desktops fit on one 256 GB box. If page sharing does not at least double the naive figure of about 120 idle 2 GiB desktops, drop density from the pitch and lead with visibility and reset alone. Either way, publish the number. Then ship the MCP server and the glass wall on top. That is the one combination nobody offers in the open in November 2026, and it is small enough for one developer to ship.
